# پاسپورت پوستی زویتر

ظاهر صفحه شروع از V1 و متن و جریان پرسشنامه از HTML یکپارچه آمده است. وضعیت انتشار و موارد باز در [فایل مرجع پروژه](PROJECT_REFERENCE.md) ثبت شده‌اند.

## اجرای محلی

Node.js 24 لازم است. برای استفاده از حساب‌ها، از `.env.example` یک `.env.local` بسازید و کلید publishable پروژه را وارد کنید. پرسشنامه مهمان با تنظیمات خالی هم اجرا می‌شود.

```sh
npm ci
npm run dev
npm test
npm run build
```

## GitHub Pages

در GitHub از Settings → Pages گزینه GitHub Actions را انتخاب کنید. کلید عمومی پروژه در workflow تنظیم شده است. workflow با نام **Build Zuyter Pages** را دستی اجرا کنید. انتشار به دسترسی Pages در طرح فعلی مخزن بستگی دارد. مسیرها با hash و فایل‌ها با آدرس نسبی کار می‌کنند تا بازکردن مستقیم یا نوسازی صفحه زیر مسیر مخزن خطای ۴۰۴ ندهد. حالت آفلاین پوسته عمومی برنامه را نگه می‌دارد. ورود، همگام‌سازی و چت اتصال اینترنت می‌خواهند.

در Supabase Auth، نشانی نهایی Pages را به‌عنوان Site URL و در فهرست Redirect URLs قرار دهید. برای لینک ارجاع همراه query string نیز الگوی مجاز محدود به مسیر همان برنامه را در Auth آزمایش کنید. برای تست محلی، URL محلی Vite را اضافه کنید. ورود پیش‌نمایش با ایمیل و گذرواژه است. ارسال تأیید ایمیل به تنظیمات Supabase Auth و ظرفیت سرویس ایمیل پروژه بستگی دارد.

## راه‌اندازی حساب مدیر و چت

پس از ثبت‌نام حساب مدیر، از SQL Editor با شناسه حسابی که مالک مشخص کرده است اجرا کنید.

```sql
update public.user_roles set role = 'administrator' where user_id = '<confirmed-account-uuid>';
```

فایل `supabase/tests/rls.sql` آزمون کوتاه دسترسی است و داده‌های آزمایشی را rollback می‌کند. نقش مشاور را پیش از افزودن حساب به فهرست مشاوران ثبت کنید.

برای چت، وجود `AVALAI_API_KEY` را در Edge Function Secrets بررسی کنید. مدل پیش‌فرض `gpt-5.4-mini` و دامنه پیش‌فرض GitHub Pages است. برای تغییر، `AVALAI_MODEL` و `ZUYTER_ALLOWED_ORIGINS` را تنظیم کنید. مقدار origin فقط شامل scheme و دامنه و در صورت لزوم پورت است. دسترسی حساب و پشتیبانی مدل از Chat Completions را با `GET /v1/models` و یک درخواست آزمایشی بررسی کنید. [مستندات رسمی AvalAI](https://docs.avalai.org/en/api-reference/introduction)

مسئول محتوا باید هر قطعه اطلاعات عمومی را در `knowledge_sources` همراه عنوان و لینک رسمی زویتر وارد کند. پس از بررسی متن و حذف ادعاهای پزشکی، مقدار `approved_at` را ثبت کند. تابع بدون منبع مرتبط پاسخ ثابت برمی‌گرداند. سؤال ارسالی و متن منابع عمومی نامزد برای AvalAI فرستاده می‌شوند. پرسشنامه، عکس، شناسه و تاریخچه حساب در درخواست مدل قرار نمی‌گیرند. مدل صرفاً شماره منبع را انتخاب می‌کند و تابع متن بازبینی‌شده همان منبع را نمایش می‌دهد. هر سؤال مستقل پردازش می‌شود و تاریخچه نمایش داده‌شده در حافظه همان صفحه است. پیش از عرضه عمومی، سیاست پردازش و نگهداری داده AvalAI را بررسی کنید.

## تست دستی کوتاه

- در موبایل، پرسشنامه را بدون ورود کامل کنید. مسیر لک را با پاسخ «بله» و بازگشت به «خیر» امتحان کنید.
- ثبت‌نام و تأیید ایمیل، ذخیره نتیجه و بازکردن مجدد حساب را بررسی کنید. سپس یک یادداشت ۱۴ روزه ذخیره کنید.
- با حساب‌های جداگانه، لینک و QR نماینده، ثبت معرفی با رضایت، ارسال مشاوره، ارجاع مدیر و مشاهده توسط مشاور را بررسی کنید.
- پس از انتشار، بازکردن مستقیم مسیر hash، افزودن به صفحه اصلی و بازکردن پوسته عمومی بدون اینترنت را در Android و iOS بررسی کنید.

## اتصال اختیاری WooCommerce

پس از تعیین سیاست انتساب، نرخ و برگشت پورسانت، و آماده‌شدن دسترسی فروشگاه، تابع `woocommerce-orders` را با JWT غیرفعال طبق تنظیمات مخزن مستقر کنید. مقدار `WOOCOMMERCE_WEBHOOK_SECRET` را فقط در Supabase Secrets و در تنظیمات webhook فروشگاه بگذارید. برای `order.created` و `order.updated` از URL تابع استفاده کنید. تابع امضای HMAC بدنه خام را بررسی می‌کند و یک snapshot داخلی بدون فیلدهای تماس می‌نویسد. برای ثبت نخستین webhook از محیط تست فروشگاه استفاده کنید. پیش از امکان نمایش سفارش یا تسویه، نگاشت حساب‌ها و رسیدگی به برگشت سفارش باید نهایی شود.
